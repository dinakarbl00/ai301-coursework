# Rubric: is this reproduction package ready to post?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| environment-recorded | The repro report's environment details, read against the issue context and repo setup requirements. | Pass when the report records the environment details that materially affect rerunning this issue, such as relevant OS, runtime/tool version, dependency version, or setup state. It does not need irrelevant system details. If the reproduction uses an environment different from the issue's target, the difference must be stated clearly enough to interpret the result. | required |
| steps-followable | The repro report's ordered actions, commands, inputs, and setup details, read with the repository's documented setup instructions. | Pass when a stranger starting from the stated environment could repeat the reproduction without having to guess a material command, input, fixture, file, configuration, or starting state. Minor omitted details that are already explicit in the repo's standard setup instructions do not fail the check. | required |
| behavior-matches | The report's output excerpts, logs, stack traces, screenshots, test output, or other artifacts read against the behavior described in the issue. | Pass when the evidence comes from an attempt that meaningfully tests the same reported behavior or condition. The bug itself does not have to occur: an honest cannot-reproduce attempt can pass when the report shows what happened instead and clearly identifies any material environment or trigger difference that may explain the result. Reject when the artifacts test a different feature, code path, input, or failure condition such that they do not provide evidence about the reported issue, or when the shown output is unrelated to the attempted reproduction. | required |
| outcome-honest | The repro report's stated conclusion read against its steps and artifacts. | Pass when the conclusion is no stronger than the evidence supports. A reproduced result must have evidence of the reported behavior. A cannot-reproduce result can pass when the attempted setup and observations are documented honestly. Reject when the report claims reproduction despite contradictory or missing evidence, or presents an inference as an observed result. | required |
| claim-appropriate | The candidate claim comment read against the issue title/body and thread. | Pass when the claim identifies the specific issue or behavior the contributor plans to investigate and states a concrete next step such as reproducing or reporting findings. It must not promise a successful fix or an unsupported completion date. A concise claim is acceptable when it is still specific enough to show what will be investigated. | required |
| repo-conventions | The claim comment and repro report read against the repo-facts contribution policy, issue/PR templates, stated bug-report requirements, and any AI-use or disclosure policy. | Pass when the comments follow the repository-specific rules that apply to the kind of content being evaluated. An AI disclosure is required only when the repository explicitly requires disclosure on issue comments, reproduction reports, or all contributor communications. A disclosure rule that applies only to code, commits, or pull requests does not by itself require disclosure in a claim or repro comment. Silence about AI passes when no applicable disclosure requirement or prohibition exists. Reject for a direct conflict with a stated rule that applies to these comments, including a missing required AI disclosure. | required |

## Verdict rule

Accept only if every required check passes. A fail or unclear result on any required check rejects the package. The verdict is binary: accept means the package is ready to post, and reject means it should be revised before posting.
